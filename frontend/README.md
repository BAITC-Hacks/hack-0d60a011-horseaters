# Электрокомплект — рабочее место закупщика

Клиентское приложение на Next.js App Router для анализа спроса, расчёта пополнения склада и подготовки заказов поставщикам. Интерфейс содержит четыре раздела: рекомендации, аналитику, заказы по поставщикам и сценарную песочницу.

## Запуск

```bash
npm install
cp .env.example .env.local
npm run dev
```

Откройте `http://localhost:3000`. По умолчанию включён самостоятельный деморежим с синтетической номенклатурой электрокомпонентов. Утверждённые позиции сохраняются в `localStorage` браузера; они блокируются для редактирования и доступны для выгрузки в Excel или XML. Сбросить демонстрационные утверждения можно очисткой данных сайта в браузере.

## Возможности деморежима

- Поиск по номенклатуре и артикулу, фильтры по статусу, категории и поставщику, горизонт 30/60/90 дней.
- Ручная корректировка количества с округлением до кратности упаковки и учётом MOQ.
- Боковая панель с объяснением расчёта, остатками, поставками в пути и иллюстративной историей продаж.
- Пакетное утверждение с подтверждением, группировка заказов по поставщикам, черновик письма и выгрузка утверждённых позиций в `.xlsx` или `.xml`.
- Аналитика с демонстрационными временными рядами, ABC/XYZ-матрицей и журналом выбросов; сценарии роста, ограничения бюджета, уровня сервиса, задержки поставки и аномальной отгрузки.

Текущие графики, аномалии и письмо поставщику сформированы локально из демонстрационных данных. Письмо является шаблоном, без вызова LLM. XML показывает структуру заказа, но конкретную схему обмена 1С потребуется согласовать с учётной системой компании. Кнопка письма создаёт черновик для копирования; автоматической отправки нет.

## Расчёт рекомендации

Для каждого товара оценивается спрос за горизонт плюс срок поставки. Учитываются исторический спрос за 30 дней, рост, сезонность, страховой запас, проектная потребность, текущий остаток и объём в пути. Положительная потребность поднимается до MOQ и округляется вверх до кратности упаковки. Валюта интерфейса — тенге (₸). В сценарной песочнице ограничение бюджета выбирает приоритетные позиции; изменения там не утверждают и не сохраняют заказы.

## Подключение FastAPI

В `.env.local` задайте `NEXT_PUBLIC_DEMO_MODE=false`, `NEXT_PUBLIC_API_URL` и `SERVER_API_URL`. Браузеру потребуется разрешение CORS на стороне FastAPI. Фронтенд ожидает `GET /api/v1/inventory` и `PATCH /api/v1/inventory/{id}` с данными по Zod-схеме `InventoryItem`, объявленной в `src/entities/inventory/model/schema.ts`.

Сейчас эти маршруты, а также серверное утверждение заказов, в FastAPI не реализованы. При отключении деморежима приложение покажет ошибку загрузки или утверждения до реализации соответствующих API. Клиентская проверка доступности использует `GET /api/v1/health`.

## Архитектура и проверка

`app/` содержит маршруты, серверный prefetch и границы гидратации. Модули в `src/` организованы по FSD: `app → pages-flat → widgets → features → entities → shared`. ESLint проверяет направление зависимостей и доступ через public API слайсов. Серверный кэш хранится в TanStack Query, а состояние выбора и сценария — в Zustand или React Hook Form.

```bash
npm run typecheck
npm run lint
npm run build
```
